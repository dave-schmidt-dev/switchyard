# Invariants — switchyard

> System contract. The harvest tool reads `area:` globs to map HISTORY bug entries
> to invariants. Per-project convention is declared in this project's README.
>
> Confirmed by David Schmidt 2026-07-20. switchyard is a **usage-aware dispatcher**
> that spreads coding tasks across subscription-backed agent CLIs (routing on live
> usage from the `gradus` project) and runs each in a disposable sandbox with no
> rights to the Mac host. Threat model: **accident-containment, not adversary defense.**

### INV-1 — Agents have no rights to the Mac host
area: ["src/switchyard/container/**", "src/switchyard/lifecycle/**", "docker/**"]
gate_test: tests/no-host-rights.test.mjs, tests/no-host-rights-vm.test.mjs
threshold: 3
rationale: The whole safety story. Neither the agent container nor the working container mounts the host filesystem, Docker socket, or host credentials. Agents operate only on the working container's copy of the code. A host mount = the agent can nuke the Mac. The gate test proves this structurally: a working container has **no host bind mount** — a bind is the only mechanism by which a host path (the FS, docker.sock, a credential dir) could enter a container — and carries only an isolated named `/project` volume. Authentication never routes through the host: the standing agent container is logged in by a human running each provider's OAuth flow **inside it** (no host credential is ever copied in), and each working container is then authenticated by copying those credential *files* container→container from the agent container — never from the host — so no host secret enters any container. Routing is decided **host-side** (the runner reads gradus's snapshot on the host), so the snapshot never enters the container either — the only inbound signal is the per-task assignment (chosen provider/model + task text), a control input that carries no host credentials or paths and confers no power over the host.

The `ExecutionBackend` seam preserves this boundary across substrates: each backend owns workspace execution and tar transport, while `execArgv(workspaceId, {cwd})` carries no mode or session parameter. Honoring `cwd` is the backend's obligation because `prlctl exec` has no working-directory field and enters a different launchd domain from the Aqua domain required by the provider.

The Parallels gate adds host-side `prlctl list -i` assertions that host-defined sharing is off, plus guest-side mount, clipboard, and C-3 checks. The C-3 ruleset is guest-side and blocks host identities, the LAN gateway, and the guest subnet while allowing internet and DNS. These guest observations prove the configured guest posture only; they do not claim host isolation, and guest root remains an accepted bypass that the non-admin provider account is required to prevent.

### INV-2 — Code returns to the Mac only through the explicit, reviewed integration step
area: ["src/switchyard/integrate/**"]
gate_test: tests/integration-gate.test.mjs
threshold: 3
rationale: The single door between the sandbox and the host. Agent output reaches real files only via a reviewed apply/merge — never a direct agent write to the host. Bypassing this is how unattended agents would silently corrupt the Mac's copy.

### INV-3 — The disposable workspace is wiped at project end, and no working object ever accumulates
area: ["src/switchyard/container/**", "src/switchyard/lifecycle/**", "src/switchyard/runner/**"]
gate_test: tests/workspace-wipe.test.mjs, tests/workspace-wipe-vm.test.mjs
threshold: 3
rationale: The disposable workspace (Docker working container + named volume, or a Parallels working VM) is the project-code/build-artifact unit; wiping it per project prevents cross-project state bleed and bounds an accident to one project. The standing agent container and the Parallels golden image are never disposable units. Disposal must hold on the ABNORMAL paths too, so no leaked object accumulates: Docker reclamation uses the object's `worker_pid` label, while Parallels reclamation parses the exact reserved `switchyard-work-<runId>-<creatorPid>` name and force-destroys only a PROVEN-dead creator PID. A live owner is never reaped, and a VM whose name does not parse is never touched or reported. A normal exit destroys the workspace; a crash is swept; a graceful signal cleans up its own workspace. The no-accumulation / reclamation-liveness half is additionally gated by tests/lifecycle-recovery.test.mjs and tests/workspace-wipe-vm.test.mjs. The live VM gate records a skip when Parallels, the stopped golden image, or a shared VM slot is unavailable; this avoids treating infrastructure absence or the Virtualization.framework guest cap as an INV-3 failure. Run-store text dirs under the state root are governed separately.

### INV-4 — A task is dispatched only to a provider with remaining usage, spreading load across funded providers; every dispatch records provider + model + result
area: ["src/switchyard/router/**", "src/switchyard/roster/**", "src/switchyard/ledger/**", "src/switchyard/adapter/**", "src/switchyard/runner/**"]
gate_test: tests/router.test.mjs
threshold: 3
<!-- Retry supplement: only verified provider-scoped signatures become quota_exhausted; an owned working-container target may be quarantined for one reset-before-reroute retry, while generic/auth/unknown failures remain terminal. -->
rationale: The product's reason to exist. Routing to an exhausted provider (percent_left at/near 0, or before reset_iso) defeats load-spreading and hits the "out of usage" wall switchyard removes. Funded providers use two routing pools in precedence, followed by one absolute-last-resort candidate. (1) Priority-fill: a roster-declared subset of "cheap implementor" providers — Antigravity (both the Gemini and Claude buckets), Copilot, and Cursor's 1st-party (`ac`) bucket — each carry a roster `implementor_priority` rank and are drained, strictly in that rank order, to a hardcoded 0% floor before any better provider is touched AT ALL; headroom is never compared across ranks (rank 1 always wins over rank 2, even holding less headroom), only same-rank ties fall to the tie-break scorer. This is a deliberate policy choice, not the general behavior: these are the cheap/lower-quality lanes David wants exhausted first, not spread alongside the rest. (2) Only once every priority-fill candidate is drained does the router fall back to the original spread behavior among the unranked remainder (Claude, Codex, opencode-go) — favoring the most remaining headroom rather than draining one before touching the next, so a plan still consumes the aggregate capacity of that pool. (3) Cursor's API (`ap`) bucket is reserved as an absolute last resort: it is never pooled with `ac` (each is matched by its own snapshot window id) and is only eligible once both the priority-fill pool AND the unranked spread pool are exhausted, gated by the ordinary 5% floor. (The provider *priority list* Claude>Codex>Agy>Cursor>Vibe>Copilot governs the order adapters are BUILT, not runtime preference.) Recording provider+model+result per task keeps dispatch auditable and feeds the capability-class → provider/model fitness record INV-5 relies on. At the adapter boundary, only verified provider-specific signatures may become `quota_exhausted`; auth, generic transport/rate-limit text, unknown providers, and near misses remain non-quota failures. The runner may quarantine only the exact canonical target from an owned working container, reset before one same-task retry, and never spend a second logical task slot. Before an eligible provider execution or orchestrator launch, the runner must complete a sanitized project-local intent receipt; descriptor-invalid and no-provider outcomes do not launch and therefore do not require an intent receipt. The legacy global ledger is a best-effort projection only, with bounded failure classifications.

### INV-5 — A task runs only on a (provider, model) whose capability class meets its RequiredCapability
area: ["src/switchyard/router/**", "src/switchyard/roster/**"]
gate_test: tests/capability-match.test.mjs
threshold: 3
rationale: Providers and models are not interchangeable. A task requiring the `high` capability class (complex integration, schema/migration) routed to a low-capability harness or small model (Vibe, Copilot, or a Haiku-class model) produces wrong work that costs more to fix than it saved; conversely, running trivial tasks on a top model (Opus, top-tier GPT) needlessly burns the premium caps switchyard exists to conserve. So capability is a hard eligibility FILTER applied *before* INV-4's spread selection — a (provider, model) below the task's `RequiredCapability` is not a candidate — and within the chosen harness the model is right-sized to that capability class. Combined with INV-4's spread this is self-optimizing: easy tasks fall to weak/cheap providers first, reserving strong providers' headroom for the tasks that need them. An omitted task field resolves to `standard`; explicit `high` or `low` requires a non-empty `RequiredCapabilityJustification` and fails before provider dispatch when absent. Review tasks use this same capability ladder without a reviewer-role route. Gemini Antigravity was re-enabled on 2026-08-13 (Gemini 3.7 Flash, `low` → Flash medium-thinking, `standard` → Flash high-thinking, no `high` slot), so it is no longer excluded by disablement — it is excluded by the same receipt rule as any other target: automatically eligible only with current exact promoted `dispatch_qualified` descriptor evidence, which it does not yet hold. Vibe is an enabled OpenCode-backed implementation target keyed by its exact `Vibe` snapshot path and roster-declared low capability, but is automatically eligible only with current exact promoted `dispatch_qualified` descriptor evidence; when the snapshot is missing, the shared OpenCode harness remains ambiguous and blind fallback fails closed rather than silently choosing Vibe or OpenCode Go. The keyword classifier remains a legacy direct-call helper, not a queue-routing fallback; invalid declared values fail closed.

### INV-6 — Run state is durable and race-free, and a project is never left permanently locked
area: ["src/switchyard/run-store/**", "src/switchyard/dispatch/**", "src/switchyard/diagnostics/**", "src/switchyard/runner/**"]
gate_test: tests/run-store.test.mjs
threshold: 3
<!-- Retry supplement: checkpoint transitions are monotonic and atomic; retry state is authoritative over derived run-store projections, status/result overlay it, and resume reconstructs an interrupted target quarantine before selection. -->
rationale: The detached dispatch lifecycle (`launch` → `status` → `result` → `recover`) persists run state to `.logs/switchyard/runs/<runId>/run.json` as the single source of truth a crashed or killed worker can be diagnosed and recovered from — the run store is the durability boundary the rest of the reliability contract stands on. Writes are atomic (a unique tmp path per write, never a fixed or shared one, so concurrent writers can't collide on the same rename) and revision-checked; concurrent writers to the same run are serialized through an in-process per-run queue so a losing writer gets an honest `RevisionError` instead of a silent last-write-wins clobber of another writer's data. A fixed-revision write is not enough on its own — two callers that both capture the same base revision before either commits will still drop the loser — so every worker-bootstrap write that can race another one (the terminal state, and each fire-and-forget event callback: `onTaskStart`, `onTaskRouted`, `onResult`, `onCheckpointSaved`) goes through `updateRunWithRetry`, which re-reads and retries against the freshest revision on conflict rather than losing to a same-instant sibling write. Every acquired run lease and project lock is released on every terminal path — success, task failure, and crash — or reclaimed by `recover`, which releases a lock only after proving it is unowned by a run that is still genuinely active (terminal or worker-process-dead), so recovering a stale run can never yank a lock out from under a different, currently-running one. A project must never be blocked from a future `launch` by a run that has already finished or died.
