Routing is decided host-side from the Gradus snapshot, so the provider receives only its task assignment (target and task text), which carries no host credentials and confers no power over the host. Failed recovery claims are retried only with ownership revalidation, so a replacement project-lock owner cannot be deleted or clobbered, while recovery recognizes a legitimate newer owner as a handoff. Terminal summaries add only the closed outcomes `completed_work`, `no_runnable_work`, `deferred_work`, `failed_work`, `failed_before_work`, `recovered_dead_worker`, or `unknown_failure`.

### Dirty tracked overlay and predecessor continuation supplement

When enabled, a simple dispatch task has an immutable receipt for its declared overlay (versioned schema version 2). The receipt hash is persisted in `run.json` and consumed by simple dispatch without recapture. In addition to exact tracked dirty inputs, simple dispatch supports bounded regular untracked prerequisite transport when explicitly declared and proven by an accepted predecessor simple-attempt durable receipt (`--predecessor-receipt <path>`). Predecessor transport binds predecessor run identity, the same canonical project, succeeded run state, base revision, relative path, byte size, and digest; caller-provided receipt bytes must exactly match the durable terminal summary. Receipt publication is owner-only and create-only; source HEAD, file mode/link count/size, and bytes are revalidated before allocation and again before integration. Rejection is fail-closed and occurs before any provider call for untracked inputs without a matching predecessor receipt, fabricated or cross-project evidence, mismatched predecessor digest/base revision, ignored, symlinked, special, secret-shaped, duplicate, traversal, out-of-scope, or drifted input. Dependent tasks run in a fresh disposable clone with no host commit. Raw overlay bytes never appear in events, results, or run-store projections.

Launcher admission supplement: every Vibe, Vibe Code, and OpenCode invocation, including health reroutes and correction, first runs the fixed harmless `/usr/bin/sandbox-exec -p "(version 1)(allow default)" /usr/bin/true` probe within the remaining deadline and a five-second process bound, with cancellation and progress. Recorder readiness precedes the health start fence. Opt-in deferred start reserves only an unstarted owned half-open claim; deadline and cancellation are rechecked after awaited reservation and all status callbacks. The controller releases a refused unstarted claim, while its one-shot synchronous `startPrepared` transition is adjacent to actual execution with no intervening await or callback. Default health `start()` callers retain their existing behavior, and an actually started claim is never released as never-started. Failed admission starts no broker/provider and consumes no half-open trial; its result is `launcher_environment_unavailable` with `providerStarted=false` and provider lifecycle `never_started`, while the existing durable taxonomy remains `environment_failure` at `preflight`. Unconfirmed probe child cleanup remains unavailable and retains owned artifacts independently from provider lifecycle. Primary started request logs survive; only identity-matched empty never-started logs can be removed for reroute, and correction writes its own bounded log in the same owned run root. Probe output never supplies provider failure authority or durable raw diagnostics. Before that probe, every simple attempt on the real provider path runs the CLI contract canary for the binary its lane execs: `--version` must parse (no version pin is enforced) and `<scope> --help` must list every flag the lane's argv builder emits, with hidden flags proven only against a parser that rejects an unknown flag. The canary runs offline in a disposable HOME with no credentials or stdin, bounded by the remaining deadline and a 30-second step bound, with progress. A timeout or spawn error is inconclusive: it admits, is never cached, and is reported as a `cli_contract_unverified` milestone. Definitive results are cached per process by canonical path, inode, size and mtime, so an upgrade in place forces a re-check.
