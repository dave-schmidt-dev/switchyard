# Changelog

Noteworthy changes follow [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/). Versions follow [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html); the compatibility contract is in [README.md](README.md).

## [Unreleased]

### Changed

- Pure failure classification, ownership, health trust, routing blame and failure-log decisions share one module, preserving prior behavior with a base-derived golden table.

### Added

- Python checks may declare one existing shared `~/.venvs/<name>/bin/python` interpreter through its exact absolute bounded pytest command. Interpreter and base prefix stay read-only; grants apply only to declared Python checks. Changed roots, symlink escapes and mixed or multiple interpreter sets refuse; `uv` remains unsupported.
- Executed acceptance checks disclose that app-target compilation remains unverified, in terminal results and durable summaries.
- Report results add bounded advisory `report.citationCheck` diagnostics for exact file/line/identifier matches, missing files, wrong ranges and unverifiable forms. Text matches do not establish semantic truth; report success and existing report metadata keep their meaning. `simple --help` now describes these diagnostics and differential test acceptance.

- `simple --integrate hold` lets a caller hold integration instead of cancelling a run: it runs every check and the integration gate but writes nothing to the project, stores the verified patch and a digest-bound receipt in the run store, releases the project lock and reports `integration.state: "held"`. `routing-run apply --run-id <id>` later integrates exactly that patch against the current HEAD after re-running the gate (and the acceptance checks when HEAD moved), or refuses with one closed reason such as `held_receipt_stale` or `held_patch_conflict`; an apply whose outcome is unknown blocks later applies rather than writing the patch twice. A held run counts as a succeeded attempt, and `routing-run inspect` lists it under `heldIntegrations`.
- A `pytest`, `python -m pytest` or `node --test` acceptance check that is already red on the base tree no longer dooms the dispatch: its per-test baseline is captured in the dry run, and a failing run after the provider is accepted when no new test fails, no baseline test disappears or becomes skipped, and the task's own tests pass. The check result records a bounded, redacted `differential` verdict. Any other check, an unusable baseline, or a report that cannot be read keeps the exit-0 rule.
- A `simple` result whose checks all passed now says how at its top level: `checkAcceptance` (`differential` or `strict`) and `toleratedBaselineFailures`, also written to `run.json`'s `terminalSummary` and to failed attempts in the failure log. A differentially accepted check is rechecked after HEAD advanced against the original base's baseline instead of failing `host_concurrency`, and the provider and repair prompts name the checks judged test by test.
- `simple --allow-executable <path>` lets one declared `--file` be created as, or changed from 100644 to, a regular executable file (100755), so a task can deliver a new test script without a manual chmod after integration. Every other new executable bit, any rename or copy, and a symlink turned into an executable still fail with `executable_file_refused`; a diff with any touched name that is not valid UTF-8 or contains a newline receives no grant; a new `*.sh` script also needs `--allow-manifest`.
- `switchyard-dispatch doctor [--quick] [--json]` gives a read-only host diagnosis: sandbox toolchain, provider CLI versions, bridge content pins, qualification expiry within 9 days, repair holds, stranded pending attempts, the canary LaunchAgent and any leftover retired VM reaper. Each check prints one line and its fix commands. Exit status is 0 when nothing failed, 1 on a failure and 2 on a usage error. `simple` prints a one-line quick-subset warning at start when a check finds a problem.
- `simple --timeout <minutes>` provides a relative 1–30 minute alternative to `--deadline`.
- Add optional `simple --estimate-minutes` admission before provider work, with deadline-fit diagnostics and a split recommendation for estimates of 20 minutes or more. Existing deadline caps and funding safeguards remain unchanged.
- Support bounded Python Quick checks through an existing project virtual environment, with candidate imports, confined caches, and matching planning-side validation.
- Add a strict host sandbox validation gate and a provider-free daily canary with local failure/recovery notifications.
- Add rollback-safe canary installation from an explicitly accepted immutable Git revision, plus an idempotent uninstaller.
- `worktree_missing` failure reason: a simple checkout deleted from outside mid-run (for example by a broad `$TMPDIR` delete) now fails with this environment code before provider-health classification, instead of `provider_group_unconfirmed`, and stops the routing run.

- `simple --origin work|qualification` labels qualification canaries separately; ordinary work remains the default, and provider eligibility and lifecycle gates still apply.
- Simple CLI tasks now bind exact task identity across renamed routing runs; unsafe, failed, pending, retained-partial, or native-latched retries link back to the original run before provider allocation. Use `--task-id` when revised prompt text should keep the same identity.
- Unrecognized failed-provider exits retain a redacted 4 KiB stderr tail in a new owner-only run artifact; JSON contains only its path, and storage refusal preserves the provider failure.
- Local checks can run installed Homebrew tools and offline Cargo checks through fixed tool-tree reads, with an exact read of `/private/etc/ssl/openssl.cnf` for TLS initialization; Cargo/Rustup state stays in the disposable runtime and host Cargo/Rustup configuration and credentials remain unreadable.
- `simple --report <path>` runs a read-only report task: the one declared report path is the only allowed change, a missing or empty report stops with `report_missing`, and success returns `resultKind: "report"` with the path, bytes and sha256.
- `simple --format <command>` runs one bounded formatter in the check sandbox after the provider and before acceptance checks. A nonzero exit is advisory (`formatStatus`), and formatter edits are revalidated against the declared scope, so an edit to an undeclared ineligible path fails closed.
- `simple cancel --project <path> --run-id <id> [--timeout-seconds <n>]` signals only a live worker whose pid and start token match the run record, then waits for the project lock release and a terminal status.
- After a soft failure, the next provider continues from the previous attempt's in-scope partial when the writer is proven stopped and the capture is verified; manifest, input and out-of-scope changes are never carried.
- Simple checks run once against the base tree before the provider starts; only a pre-provider environment-broken dry run records its check identity and evidence. It stops as `check_environment_failed`, and a later matching command in the same run stops as `check_known_broken` before an attempt is allocated. Post-provider acceptance failures never enter this memory.
- Simple routing skips targets whose observed p80 duration cannot finish inside the deadline (never under `--only-provider`; an all-slow pool is kept and flagged).
- A check setup failure records the failing prepare step, a bounded error code, syscall and executable in `failureDetails` (never the error message), and an environment-broken dry-run check names the executable it resolved in the sandbox and on the host.
- A closed failure-reason registry, with golden parity against the previous classifiers, now owns cause, category and severity; run records persist the failure reason, scope-rejection detail and invocation failures, and still read with the previous release. Failure-log fingerprints include the reason, so recoding an older reason changes its fingerprint.
- Simple dispatch can run Claude Code (`--only-provider claude-code`, Haiku 5.5, Sonnet 5.5 or Opus 5.5 with an explicit effort) in a native Seatbelt sandbox on its own subscription login. It is never chosen automatically, and auth, missing-model and usage-limit failures are classified for routing.
- `switchyard-dispatch routing-run release-partial --task-id <id> [--discard]` frees a retained partial worktree after the captain salvages it, so the routing run can continue without losing its failure memory. It verifies the worktree claim and refuses symlinks, a held project lock or ambiguous cleanup.
- `switchyard-dispatch routing-run close-pending --project <path> --routing-run-id <id> --task-id <id>` recovers a dangling pending attempt only after the matching run is terminal, its writer is quiescent, no project lock is held, and no retained worktree remains; it records the attempt as skipped with reason `lifecycle_recovered`.
- A failed simple check redacts credential-shaped tokens before tail truncation (16 KiB per stdout/stderr, kept in owner-only local files under `check-evidence/` as `<attempt>-<check position>.log`, attempt 0 is the baseline) and never returns raw evidence in JSON; the result carries only that path. Diff rejections report a closed reason kind and up to five bounded, control-character-free paths.
- Simple run records now move to `running` with `startedAt` when the provider starts and record a throttled heartbeat, instead of staying `created` until integration.
- Simple attempts check the provider CLI's contract before launch: `--version` must parse and `--help` must list every flag the lane passes, offline and without credentials. A CLI that dropped a flag (OpenCode 2.x dropped `run --variant`) now fails as `provider_cli_contract_failed` before any provider start, with the missing flags and a remedy, and routing moves to the next target. `npm run cli:canary` reports every adapter.
- Simple routing logs every failed attempt and every non-complete stop to `<stateRoot>/failure-log/failures.jsonl` (allowlisted fields only, rotated, best-effort), and `switchyard-dispatch routing-run failures [--since <RFC3339>] [--json]` groups them by fingerprint for periodic routing and provider tuning.

### Security
- Claude Code and Vibe Code providers can no longer write their clone's git control files. The native launcher Seatbelt profile now denies writes to `.git` itself, `config` (and its lock and worktree variants), `hooks`, `info` (except `info/refs`), `objects/info` (except `packs`) and `refs/replace`, so a stray `git config`, hook or `git gc` fails inside the provider run instead of discarding the finished checkout as `git_control_tampered`. The index, objects, refs and logs stay writable, and the post-run `.git` verification is unchanged. OpenCode Go and Vibe (keyless bridge), Antigravity and Copilot still only detect such writes; Codex's own `workspace-write` sandbox already denies all of `.git`.
- Every provider prompt now forbids git commands that write to the repository and any change under `.git`; read-only git commands stay allowed.
- Known gap, now documented: a Quick check, under both the base and the `xcodebuild build` profiles, and a provider run under Switchyard's native launcher profile (Claude Code, Vibe) or Codex's own Seatbelt sandbox (other harness sandboxes unverified) can read the argv and environment of other same-user host processes through `KERN_PROCARGS2`, including `bws-secret-exec` children. A check keeps what it reads on the host (at worst in its owner-only `check-evidence` log); a provider can pass it to its model endpoint. Seatbelt cannot block that read and a separate account was declined, so the README threat model records it and `tests/runner-quick-checks-sandbox-procargs.test.mjs` tracks the check side as a `todo`.
- A renamed or copied executable no longer keeps its bit unseen. A pure rename or copy patch states no mode, so the destination silently stayed executable without `executable_file_refused` or `--allow-executable`. Simple's provider captures and its peer-history diff now never detect renames or copies (`--no-renames`, whatever the host config says), so a move is a delete plus a create with both modes stated, and `validateDiff` refuses any rename or copy line it still receives as `executable_file_refused`. Moving a plain declared file still integrates. Moving an executable now fails even with `--allow-executable`, because deleting an executable is never granted; copying an executable, or moving a file and setting its bit, needs `--allow-executable` on the destination. A peer commit that renames or copies an executable stops the run as `host_concurrency`.
- Host-detected Git control tampering now retains only closed `{kind, area}` evidence in the result, run record, routing attempt and failure log; provider-controlled paths and messages remain excluded.
- Host git calls on a provider-writable disposable clone pin `core.fsmonitor`, `core.hooksPath`, `diff.external`, `core.attributesFile` and `core.commitGraph`, and the clone's `.git` control state is snapshotted before the provider runs and verified, case-insensitively, before every host git read. Tampered, unreadable or redirected control state (hooks, config, alternates, http-alternates, replace refs) fails closed as `unsafe_diff` with diagnostic `git_control_tampered` and a closed-enum `gitControlTamper {kind, area}`; a trusted shared-clone detach is accepted.
- Updated the locked `smol-toml` dependency from 1.7.0 to 1.9.1, clearing the high-severity `npm audit` findings GHSA-7w5x-hrqm-74c2 and GHSA-r4xh-jqrq-34v2 (denial of service on malformed TOML); `npm audit` now reports no vulnerabilities.

### Changed

- `doctor`'s `provider-clis` check now runs the launch-admission CLI canary instead of its own `--version` probe, so doctor and launch admission can no longer disagree about a CLI. It prints one detail line per adapter (ok with its version, or the failing reason) and the canary's fix hint; a dropped flag or an inconclusive run warns, and a missing or unreadable CLI fails. Doctor no longer compares CLI versions with `ops/macos-vm/cli-manifest.txt`; `sync-host-clis.sh --check` still does.
- **Breaking (library):** `GOLDEN_IMAGE_VERIFIED_PROVIDERS` is now `QUALIFIED_PROVIDERS` (same providers, same order). The list now only scopes simple-dispatch route health and `switchyard-dispatch health identity`; the VM golden image it was named for is gone.
- A codex HTTP 401 (`failed to connect to websocket: HTTP error: 401 Unauthorized`, or `unexpected status 401 Unauthorized`) on its own line now classifies as `auth_expired`, not `provider_exit_nonzero`. The forms apply only to the codex binary. A codex 401 therefore no longer counts toward simple route-health suppression, and it reads as a re-login cause.
- A simple stop caused by a check environment that could not be set up is labelled `check_setup_failed` instead of `baseline_failed`, so it is not read as a red check or a provider failure. The attempt keeps `baseline_failed`, the target stays unblamed, and routing state stays version 1. The `simple` JSON result now carries `stopReason` for every `stop` direction; `failureReason` is still the engine's own reason.
- The stabilization freeze is lifted. README and INVARIANTS now record the 2026-09 observation window as closed (39 ledger rows, last kept 2026-09-13); routing-policy, provider-enablement and quota changes still need the owner's go.
- Receipt renewal moved from the queue to `simple`: after every succeeded `simple` run (work or qualification origin) Switchyard calls `~/.agent/bin/roster renew <run.json> --file <roster>` against the roster it routed from, bounded to 30 seconds with progress on stderr. A renewal failure never changes the run's result or exit status.
- Test lanes come from a `// @test-phase:` pragma on each test file instead of hand-kept lists in `package.json`, and an untagged file fails both lanes. The serial lane now runs in lexical order.
- Every `node --test` that the test, validate, contract-gate, coverage, mutation and canary scripts spawn runs under a hermetic environment: `HOME`, `TMPDIR` and the Switchyard state roots point into one per-run scratch directory, so tests no longer read or write the owner's roster or state.
- The OpenCode Go simple bridge runs Homebrew's OpenCode 2.x (`/opt/homebrew/bin/opencode`) instead of a fixed 1.18.30 copy, so Homebrew upgrades no longer need a bridge change; the CLI contract canary now checks `run` and `serve` flags first. OpenCode 2.x has no in-process run mode, so the bridge starts a password-gated `opencode serve` on one loopback port, waits for that server's own listening line, then runs `opencode run --server`; the Seatbelt profile opens only that port beside the proxy. The approved model's endpoint override now sits on the catalog model, and a fixed `--title` drops the extra title request.
- Orphaned-lock remediation takes project lock names from the run store instead of keeping its own copy of the hash, so the two can no longer drift apart and leave a stuck lock unfindable.
- Persist closed, deduplicated route-refusal reasons in caller and durable evidence, distinguishing funding exhaustion from capacity exhaustion.

- Cursor routing requires finite, nonnegative pace data for both `ac` and `ap`; missing data excludes with `budget_pace_unavailable`, negative pace with `budget_pace_exceeded`, including blind and pinned routes. This eligibility gate does not impose a hard spend cap across simultaneous jobs using one snapshot.

- The pre-provider dry run records which acceptance checks already fail plainly on the unmodified tree (`redAtBaseline`); the provider prompt and the repair prompt name them so the provider stops chasing failures that predate the task. Acceptance is unchanged: every check must still pass.
- Simple roots now live in an owner-only `$TMPDIR/switchyard-simple-roots/` parent instead of directly in the shared temp directory; the orphan collector scans both locations, and the broad temp sweep never selects the parent.

- Simple status exposes active task identity, deadline, validated descriptor and observed phase.
- The simple target/descriptor table, retained-partial and pending-attempt recovery, and best-effort stop logger now live in focused modules; parser and routing-run public exports and runtime behavior are unchanged.
- The simple routing waterfall's route callback, attempt evaluation and stop decisions, and reroute policy now live in focused modules beside `routing-run.mjs`; its public exports and runtime behavior are unchanged.

- Cancellation carries closed `cancelSource` values `signal_sigterm`, `signal_sigint`, `internal_deadline` or `unspecified` only on cancelled failures, while normal exit 76 remains an ordinary exit.
- The CLI routing envelope exposes `exhaustionCause` (`capacity` vs `task_failures`) for fallback authority.
- Simple dispatch enforces route health by default on lifecycle-backed provider failures (three in six hours suppresses the target on a 5/15/60-minute ladder); check, scope, sandbox and environment failures never count. Stranded health claims are reclaimed. The queue stays in shadow mode.
- A `quota_exhausted` attempt marks that target ineligible for an hour across the routing run, and a provider that reports a rate limit on stderr is stopped at once and classified `quota_exhausted`.
- A provider that exits nonzero or by signal at the caller's deadline is coded `provider_deadline_exceeded` instead of a nonzero exit.
- Sandboxed checks may run git, python3, make, swiftc, `swift build`, `xcodebuild build`, approved Homebrew tools, offline Cargo checks against the configured default installed Rust toolchain, and the project venv; they read fixed tool trees, declared path dependencies, and the exact `/private/etc/ssl/openssl.cnf` literal for TLS initialization. A PATH-scoped `xcrun` shim answers SDK queries from `DEVELOPER_DIR` and delegates tool invocations through the checker PATH; `SDKROOT` avoids host Xcode-selection and license probes. Swift package checks must use `swift build --build-system native --disable-sandbox`. Checks that use shell expansion, denied host tools or absolute paths outside the clone are rejected at argument parse.
- Eligible undeclared edits are kept, returned in `undeclaredPaths`, and flagged for the captain instead of failing the run, and the project HEAD may advance on unrelated commits during a run.
- The project lock is released before slow cleanup, and a provably dead holder's lock on a terminal run is reclaimed (`project_lock_reclaimed`).
- Biome now fails on unused imports, variables and function parameters; existing unused imports and exports were removed.
- Simple routing now separates hard and soft failures. Failed checks, empty diffs, provider errors, provider-phase environment failures and scope rejections move on to the next eligible tier 1 or tier 2 target (up to four attempts per task) instead of stopping the run; baseline, cleanup, cancellation, input, lock and run-store failures still stop. `native_required` reports whether capacity or task failures exhausted the targets, and every answer lists retained partial worktrees.
- `switchyard-dispatch simple --help` and the README now state that `--deadline` is capped at 30 minutes ahead, that tasks in one project serialize on the project lock (`PROJECT_LOCK_HELD`, even across routing-run IDs), and that `--check` runs through `/bin/sh -lc` except package-tool launches, which run as plain argv.

### Fixed

- Held apply keeps bounded original differential baselines in schema-2 receipts, so an unrelated peer commit can still pass while a new failure refuses. Invalid stored baselines refuse; older receipts and aggregate test-count/byte overflow recheck strictly.
- Environment-failure exhaustion remains `task_failures` when the same logical task resumes in another invocation, without provider exclusion or native latching.
- Detached-helper test fixtures wait for signal-handler readiness and retain a bounded lifetime past delayed teardown; sandbox toolchain probes use the remaining overall canary budget. Pre-push logs the full gate, preserves its exit status and prints failures/load; canary diagnostics distinguish timeout, signal, spawn failure and sandbox denial.
- A throwing manifest warning sink no longer replaces the original refusal. Milestone, heartbeat and provider-start reporting is extracted while the coordinator retains execution and cleanup ordering.
- Doctor repair-hold commands now use the current simple configuration epoch. An attestation for an old epoch no longer appears ready for a current trial, and inactive descriptor holds remain visible without a misleading repair command. Route health and attestation policy are unchanged.

- A routing warning sink (`onRoutingWarning`) that throws no longer changes a `simple` route. The generated-routing-ID, continuation-partial, route-exhaustion and failure-log warnings now share the containment the route-refusal warning already had; before, a throw there rejected the task or replaced its answer.
- A `simple` run whose deadline runs out during diff capture, routing, workspace preparation, repair or integration (`deadline_expired`) is no longer coded as a scope rejection. It used to resolve to `errorKind: policy_violation` and cause `scope_rejected` (routing reason `policy_rejected`). It now resolves to `errorKind: environment_failure` and the closed cause `deadline_expired` (category `environment`, routing reason `environment_failure`) in the result, `run.json` `lastFailure` and the failure-log attempt record. A deadline in a singular `check` phase is now `acceptance_check_timeout` like the `checks` phase. Provider, checks, baseline, caller-input and cleanup deadlines are unchanged.
- A Vibe or opencode-go `simple` attempt whose keyless bridge reports `provider terminated before a verified completion (... signal X, interrupt Y)` no longer records an `unrecognized` provider signature. A signal or interrupt now records `providerSignature: provider_killed`, or `provider_deadline_exceeded` when the bridge's own duration limit fired or the runner's deadline stopped the attempt. A spawn error with neither field set stays unrecognized. The cause code is unchanged (`provider_exit_nonzero`, exit 76), so routing and route health see the same evidence as before.
- A `simple` check that fails inside the checker sandbox now names the path it was denied. The path is read from the check's redacted stderr or stdout tail: a Seatbelt `deny(N)` trace, or an `Operation not permitted`/`EPERM` line from sh, git, Node or Python. It is recorded as `sandboxDeniedPath` in `failureDetails` and in the failure-log attempt and stop records, and a failed sandboxed `npm ci` setup names it too. A line that cannot be read unambiguously names nothing. The path is evidence only and never changes how the failure is classified.
